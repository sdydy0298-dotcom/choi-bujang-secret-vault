## 화면에서 무엇이 달라졌는가

1. 학생 카드 안의 관제 대시보드 첫부분에 **핵심 기능 3가지**가 순서대로 나옵니다.
   - 01 시스템 자원: CPU·메모리·디스크
   - 02 네트워크 보안: 외부 네트워크 인터페이스·IPv4·Windows 방화벽
   - 03 시스템 기록: Windows System·Application 로그의 최근 24시간 경고·오류 건수
2. 네 상태 카드(CPU, 메모리, 디스크 여유, **SDP 연결 상태**)는 그 아래에 **그대로 유지**합니다.
3. 기존 3일차 네트워크/방화벽/Windows 이벤트 정보와 비교 기능, 아래쪽 CPU/메모리 추이와 최근 측정 기록을 그대로 유지합니다. 제공 화면에 이미 있는 새로운 기능을 별도로 만들어 중복 호출하지 않습니다.
4. 버튼은 초기 **조회**, 결과가 있는 뒤 **다시 조회**, 요청 중 **새로 읽는 중…**을 나타냅니다. 응답이 오기 전에는 기존 데이터를 새 값처럼 표시하지 않습니다.
5. **조회하지 못한 항목 n개** 상자에 항목명·이유·다음 행동을 표시합니다. 일부 항목만 실패한 경우 실패한 항목만, API 전체 실패인 경우 여섯 항목을 구분합니다. 권한 부족 시 관리자 권한으로 바꾸지 않습니다.
6. Tab으로 조회 버튼까지 이동해 Enter나 Space로 실행할 수 있습니다. 조회를 시작하거나 완료하면서 제공 UI가 학생 칸을 다시 그려도 버튼 초점을 다시 잡아 줍니다. 대기 중 중복 요청은 막고, 자동 재시도는 없습니다. 최근 측정 기록 영역은 Tab으로 초점을 이동해 방향키로 스크롤할 수 있습니다.
7. 안내 문구와 실패 상자에 보조기술용 상태 속성을 사용합니다. 실패 상자는 **새 실패 결과를 수신했을 때 한 번만** 알림 역할을 갖도록 합니다.

## 실제 데이터와 예제 데이터의 차이

- **실측**: 공식 0.2.21 로컬 API `GET /api/pc/status`에서 `source: "local-pc"`, `schema: "aleph.on.pc-status.v1"`, 최근 측정 시각이 검증된 응답만 표시합니다. 각 항목은 별도로 성공/실패를 판단합니다.
- **예제**: SDP·XDR 제공 데이터의 `mode: "demo"`는 예제 데이터입니다. 실제 사용자의 PC 측정 결과와 혼합하지 않습니다. PC 실측이 성공해도 SDP는 `SDP 미연결`일 수 있습니다.
- **실패/미실행**: `조회 전`, `새로 읽는 중…`, `확인 불가`, `조회 실패`를 구분하며 **가짜 수치를 넣지 않습니다**.
- Windows 이벤트 경고/오류 건수는 **침해·공격 탐지 건수가 아닙니다**. 조회 범위와 최대 5,000건 표본 제한을 유지하며, Windows 설정을 읽기만 하고 수정하지 않습니다.

## Windows PC에서 기존 공식 0.2.21 보존하며 가져오기

**중요**: GitHub의 `keshev-final-assault` 브랜치에는 학생 변경 사항과 함께 구버전 0.2.11 제공 파일도 남아 있습니다. 이미 로컬에 안전하게 업데이트된 공식 **0.2.21을 되돌리지 않기 위해 `git pull`, `git switch`, `git reset --hard`, `git clean` 등을 하지 마세요.**

기존 `keshev-final/on-client` PowerShell(일반 사용자 권한)에서:

```powershell
# 기존 케셰브 서버는 Ctrl+C로 종료
# 3일차 학생 파일에서 개인 편집이 생기지 않았는지 Git blob 해시로 확인
$expected = "400de3c4e0507a31e4b443a697f16915b598223f"
$actual = (git hash-object --path=on-client/student/extension.mjs -- .\student\extension.mjs).Trim()
if ($actual -ne $expected) {
  throw "student/extension.mjs 에 3일차 이후 별도 수정이 있습니다. 덮어쓰지 말고 차이를 먼저 확인하세요."
}

git fetch origin refs/heads/keshev-final-assault:refs/remotes/origin/keshev-final-assault

# 두 파일만 가져옴: 제공 public/src/package.json 파일에 손대지 않음
git restore --source=origin/keshev-final-assault --worktree -- student/extension.mjs docs/STUDENT_DAY4_UI.md

(Get-Content .\package.json -Raw | ConvertFrom-Json).version
npm.cmd run check
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

`0.2.21`이어야 합니다. 보호할 3일차 해시가 다르다면 에러를 보존하고 멈추세요. 이 절차는 기존 제출물·이전 브랜치·공식 0.2.21 원본을 변경하지 않습니다.

## 직접 검증할 순서

1. `http://127.0.0.1:5189/` → `Ctrl+Shift+R` → **보호 현황** → **학생 상태·알림 표시** → **내 PC 관제 대시보드**.
2. 상단 **핵심 기능 3가지** → 4개 상태 카드 → 네트워크/방화벽/Windows 이벤트 → 추이/기록 순서를 확인합니다.
3. 측정 전 상태는 `조회 전`입니다. 키보드 **Tab**으로 `조회`를 선택하고 **Enter**로 실행합니다.
4. 느리게 조회할 때 `새로 읽는 중…`·대기 상태가 표시됩니다. 조회 중 Enter를 반복해도 **중복 조회하지 않아야** 합니다.
5. 조회가 끝나면 `실측 6/6` 또는 일부 `확인 불가`와 원인이 보입니다. 결과가 나오고 버튼이 `다시 조회`로 돌아와도 초점을 유지해야 합니다.
6. **다시 조회** 후 CPU·메모리 값, 아래 사용률 추이와 측정 기록이 갱신되는지 봅니다.
7. Tab으로 `최근 측정 기록` 영역에 초점을 이동해 **방향키 위/아래**로 스크롤할 수 있는지 확인합니다. 기록에 CPU·메모리 값과 측정 시각이 있어야 합니다.
8. 요청 실패 검증: **Ctrl+C**로 서버만 중지하고 브라우저에서 `다시 조회`를 누릅니다. `조회하지 못한 항목 6개`, 실패 이유와 `5189 포트 서버 확인 후 다시 조회` 안내가 나와야 합니다. 이전 측정값이 현재 상태 카드에 남으면 안 됩니다. 그 다음 평소 명령으로 서버를 다시 켭니다.
9. 권한이 없어 항목 하나가 조회되지 않으면 항목명/읽기 권한 없음/담당자 문의가 나오는지 확인합니다. **권한이나 방화벽 설정을 일부러 바꿔서 시험하지 않습니다.**
10. `student/appearance.json` 오류가 나타나지 않아야 하고 기존 메뉴(업무 앱·보안 기록) 및 제공 UI가 동작해야 합니다.

## 검증 상태

- 변경된 학생 소스는 문법 분석과 **모의 API 응답 기반** 점검을 통과했습니다: 6/6, 일부 4/6, 전체 API 실패, 이벤트 건수 제한, SDP demo, 키보드 포커스/대기 표시, 실패 알림 반복 방지 등.
- 이것은 **모의 응답 점검**일 뿐이며 Windows 실측 및 실제 브라우저 키보드 조작의 최종 증거는 위 절차로 사용자가 확인해야 합니다.
