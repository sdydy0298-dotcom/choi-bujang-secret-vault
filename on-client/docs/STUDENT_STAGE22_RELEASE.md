원본 기능 파일을 새로운 폴더로 가져와 실행할 때, **HEAD가 제출 SHA와 일치하지 않으면** 원본 재현이 아니다. 확인 후 문서나 코드에 변경이 있으면 새 SHA로 다시 수행해야 한다. 과거 stage별 별개 제출·모의 테스트 성공을 합쳐 현재 최종 버전 전체 성공으로 단정하지 않는다.

## 2. 용어와 증거 수준

- **SRC (원문 확인)**: 해당 GitHub 소스의 함수·입력 계약·파일 경로·구조를 읽어 확인. 실제 서비스 요청·출력 검증 아님.
- **MOCK (모의 DOM 검사)**: 이전 단계에서 격리된 DOM과 가짜 입력으로 화면 분기만 검사. 실제 SDP·CLCO·OSV 통신 아님. 현재 최종 HEAD에서 재실행되지 않았다면 최종 결과로 인용하지 않음.
- **SCREEN (기존 화면·학생 보고)**: 이전 사용자의 로컬 화면과 오류를 보았다는 사실. 새 환경에서 같은 SHA를 재현했다는 뜻이 아님.
- **RUN (환경 실제 실행)**: 실행 폴더 HEAD와 명령, 응답, 환경, 시간 증빙이 일치하는 경우만. 외부 네트워크 때문에 소스를 못 받은 기록은 RUN-FAILED.
- **OFFICIAL (ALEPH 피드백)**: 서버가 읽은 커밋과 검사 결과. 서버는 새 환경을 실행하지 않으므로, 통과 기록도 자동으로 운영 집행을 보장하지 않음.
- **UNV (확인 불가)**: 이번 최종 제출 커밋에서 실제 수행하지 않음, 미지원, 자격 미확보, 결과 확인 불가. 실패 또는 성공으로 채우지 않음.

아래 표의 시간은 원문/이전 이력의 **확인 시각**이며, 새 Windows 폴더에서 최종 HEAD를 실행한 시각이 아니다. 새 환경 직접 결과는 별도 [재현 기록](STUDENT_STAGE22_REPRODUCTION.md)에만 추가한다.

## 6. 인수 조건과 미해결 이슈

- 새 환경에서 **제출한 40자리 커밋 그대로** clone, Node 점검, 실행, 브라우저 3개 메뉴, 종료, 재기동한 실제 증거가 있어야 최종 환경 재현을 확인했다고 말할 수 있다. 이번 문서 작성 시 미확인이다.
- 사용자 PC 인증·Native 호스트 승인·실제 AI 설명은 실제 학생 신원 매핑 및 운영자 준비가 필요하다. 이전 401/409 이력을 연결 완료로 바꾸지 않는다.
- 19단계의 실제 지원 조치·사람 확인·원천 집행·효과 재조회는 미완료다. 학습용 모의 집행은 원천 성공이 아니다.
- 운영자 승인 OSV 대상과 실제 설치 패키지/버전 확인 전에는 안전함·취약점 없음이라고 단정하지 않는다.
- 21단계 공식 AI 판정은 최신 커밋에 대해 확인되지 않았으며 이전 비밀 감지 문제 이력이 남아 있다.
- 실제 보존 기한, 운영 인증, 사용자 권한, 외부 백업 보관 장소는 별도 운영자 결정 사항이다. 학생 임의로 부여하지 않는다.
- 버전 표기는 **0.2.11 기반 검증 중**. 전체 실제 재현과 원천 집행·운영 인수 확인이 되기 전에는 릴리스 v1.0을 만들지 않는다.

### 제출 기록

이 문서는 소스와 함께 Git 커밋한다. 사용자는 22단계 화면에 저장소 URL과 현재 브랜치 HEAD **40자리**를 직접 입력한다. 21·22단계는 Workbench의 13~20단계 제출 준비 기능으로 제출하지 않는다. 비공개 제출의 원문 JSON은 공식 전달 도구를 사용하며 개인 보안 설정은 포함하지 않는다. **AI가 커밋 원문을 읽어 통과했더라도 실제 학생 PC 재현이나 운영 집행 성공을 인증한 것은 아니다.**
