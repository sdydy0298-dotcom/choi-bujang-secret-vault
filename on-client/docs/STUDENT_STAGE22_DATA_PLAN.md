# 케셰브 22단계 - 데이터 보존, 안전한 백업 및 복원 계획

> 작성 2026-10-23. 이 문서는 수행 가능한 순서와 **권한 경계**를 설명하는 계획이다. 실제 운영 원천의 백업·복원 작업을 실행했거나 검증했다고 주장하지 않는다.

## 1. 보존 대상을 서로 구분한다

| 구분 | 실제 코드상 근거 | 보존 담당 및 제한 |
|---|---|---|
| **학생 작성 소스·문서** | Git 저장소의 on-client/student, on-client/docs, on-client/STUDENT_README.md 및 제공 실행 경로 | 학생이 제출 40자리 커밋을 Git 원격에 보관. 원본 폴더와 Git 기록을 보존하고, 새 폴더는 clone으로 생성 |
| **실제 접속 판정·XDR 기록/세션·기기 데이터** | on-client/src/engine/sdp-host.mjs의 기존 원천 조회 | **기존 SDP/보안 원천이 보존·백업·복원**. 케셰브 화면에 표시됐다는 사실로 학생 PC 저장본이 생기는 것은 아님 |
| **계정 승인/AI 앱 보관함 및 레지스트리 자료** | on-client/src/connection/native-context.mjs, src/ai/credential-vault.mjs. Windows 개인 영역과 프로젝트 바깥의 별도 경로 | 접근 가능한 학생/운영자만 관리. 신규 폴더에 그대로 복사하거나 Git에 포함하지 않음. 승인과 신원 확인을 통해 별도 재연결 |
| **선택적 조치 기록용 SQLite** | on-client/src/actions/store.mjs는 이미 존재하는 별도 SQLite databasePath만 허용. alekov_action_intents, alekov_action_state, alekov_action_audit 테이블 사용 | 실조치 운영 연결이 준비된 경우 **해당 DB 소유 시스템/운영자**가 일관성 있는 백업·검증·복원을 담당. 현재 학생 개인의 실집행·복원 검증 없음 |
| **취약점 조회(OSV) 기록** | on-client/src/vulnerabilities/project-scan.mjs, osv.mjs | 공개 허용 목록을 사용한 조회 결과. 결과가 없거나 일부 실패면 취약점 없음으로 저장하거나 판정하지 않음 |
| **로컬 학습용 화면·모의 입력** | public/app.js, student/extension.mjs의 상태 표시 | 예제와 미확인을 구분. 임시 모의 테스트를 실제 학생 보안 데이터로 보존하지 않음 |
| **기존 1~12단계 소스/데이터** | 저장소 최상위 README.md, package-lock.json, data.json 및 관련 모듈 | **케셰브 13~22단계와 별도 범위**. 임의 수정·삭제·덮어쓰기 금지 |

코드에 보존 기한·운영 백업 주기·접근 권한을 정할 근거가 없으므로 일수·용량·운영 권한을 임의로 선언하지 않는다. 운영 원천의 실제 보존 정책은 해당 운영 담당자가 결정한다.

## 2. 학생 소스 보존

1. 원본 프로젝트에서 git status --short 및 git rev-parse HEAD로 미커밋 변경이 있는지 확인하고 기록한다. 저장하지 않은 변경을 소거하지 않는다.
2. 새 문서는 별도의 학생 파일로 작성하고 하나의 Git 커밋에 보존한다. 저장소 주소·브랜치·40자리 HEAD를 인수 문서/제출란에서 동일하게 관리한다.
3. 재현은 **기존 폴더를 교체하거나 이동하지 않고** [새 폴더 재현 절차](STUDENT_STAGE22_REPRODUCTION.md)대로 clone/checkout한다. 원본 폴더는 그대로 둔다.
4. 원격 Git 저장소가 유일한 복구 수단이 되지 않도록, 필요 시 조직 정책상 허용된 별도 보호 저장소에 **보안 점검 완료된 소스 아카이브**를 보관할 수 있다. Git 기록에는 예전 비밀 값이 포함될 수 있으므로 히스토리 전체를 외부에 공유하거나 무조건 동기화하지 않는다.
5. 제출 커밋의 진위를 확인한 후 새 작업 폴더에서 on-client/package.json / tools/start-alekov.ps1 / docs 자료가 존재하는지 확인한다. 버전이나 변경이 발생하면 새 SHA로 증거를 분리한다.

**실제 백업 실행 관측:** 이 문서를 만드는 과정에서 개인 PC 원본·운영 데이터·사용자 자격 자료의 백업을 수행하지 않았다(UNV). GitHub의 기존 브랜치·커밋과 이번 학생 문서 보존은 코드 수준에서만 확인한다.

## 3. 설정과 비밀 자료를 복사하지 않는 이동 계획

- 예시 설명은 on-client/.env.example의 **비밀 없는 구조**에 한정한다. 개인 설정 파일과 외부 서버 자격 자료는 Git/문서/제출 JSON에 포함하지 않는다.
- 호스트 연결 설정은 프로젝트와 별개이며, 소스 복제만으로 앱 전용 권한·기존 SDP 사용자 식별·원본 보관함이 복원되는 것은 아니다.
- 새 폴더는 연결 없음(disconnected) 모드에서 먼저 확인한다. 운영자가 별도로 현재 사용자·프로젝트·앱 권한을 검증한 뒤에만 원천 연결을 검토한다.
- 사용자가 별도 인증·설정 자료를 분실한 경우, **Git 소스에서 추정 복원하거나 이전 사용자 자격을 복제하지 않는다**. 정식 발급·승인 경로를 이용한다.
- 파일 내용을 채팅·로그·스크린샷·원문 묶음에 출력하지 않는다. 제출 단계에는 저장소 및 비밀 제외 문서만 사용한다.

## 4. 실제 데이터·DB 보존과 복원(운영자 수행 구간)

| 순서 | 안전한 조건/방법 | 수행 상태 |
|---|---|---|
| 1. 대상 확인 | 현재 소유 주체, 사용자/프로젝트 범위, 조치 실행 여부, 기존 엔진 버전, 백업 시점·보존 정책을 **원천 운영자**에게 확인 | UNV |
| 2. 백업 생성 | 원천 SDP DB/XDR 로그/별도 SQLite가 있다면 해당 **시스템에서 지원하는 일관된 백업 절차**만 사용. 운영 중 파일을 임의 복사하지 않음 | UNV |
| 3. 백업 검증 | 비밀 제외 메타데이터 기준으로 백업 상태, 무결성, 원천 시스템 범위, 버전을 점검. 불일치 시 복원 금지 | UNV |
| 4. 별도 격리 복원 | 운영자가 허가한 비운영 환경에서 복원 후 동일 소유 범위의 사건·기기·세션을 대조. 사용자 PC에서 임의로 실서버를 덮어쓰지 않음 | UNV |
| 5. 사후 확인 | 개별 기존 데이터, 시간·버전·접근 범위·권한, 요청 영수증/효과를 **원천 기록**으로 확인. 읽지 않은 데이터나 실패한 결과를 성공으로 기재하지 않음 | UNV |
| 6. 문제 발생 시 | 이전 정상 백업과 원천 담당자 복구 절차를 이용. 무단 재집행·반복 복원·데이터 삭제 금지 | UNV |

추가 주의: on-client/src/actions/store.mjs의 조치 테이블에는 이전 이력 변경·삭제 방지 제약이 있다. **학생 임의 UPDATE/DELETE, 파일 교체, 같은 요청 재집행**으로 복원을 시험하지 않는다. 준비/ACK/성공 확인을 구분하고, 원천의 observation.effectApplied 확인 없이 성공으로 기재하지 않는다. 현재 기본 supportedActions가 빈 배열이므로 실제 학생 보안 조치 복원 실습은 미수행이다.

## 5. 재현 이후의 인수·검증 기록 양식

| 필수 기록 | 확인할 출처 | 지금 기록 |
|---|---|---|
| 원본/새 폴더 HEAD (40자리) | 두 PowerShell의 git rev-parse HEAD | 원본 Windows: UNV / 새 Windows: UNV |
| Node.js 버전과 새 실행 폴더 | 새 폴더에서 node --version, git status --short | UNV |
| HTTP 화면과 종료/재실행 | 5190 루프백 HTTP, 화면 3메뉴, Ctrl+C | UNV |
| SDP·XDR 조회 성공 여부 | 원천 응답/범위. disconnected는 성공 아님 | UNV |
| AI 연결/사건 설명 | 앱 전용 권한과 실제 설명 수신의 별개 확인 | UNV |
| 조치 처리·효과 | 사람 확인, receiptId, requestId, 실제 원천 관측 | 기본 미지원/UNV |
| 패키지 OSV | lock 메타데이터, 허용 목록, 정확한 버전, 응답 시각 | UNV |
| 백업/복원 | 운영자 대상·백업 버전·복원 환경·데이터 비교 | UNV |

기록 시각과 로그는 실제로 관측한 뒤에만 채운다. 화면 그림·AI 원문 판정·학생 진술은 새로운 원천 검증 성공의 대체 근거가 아니다. 결과 미확인 상태에서는 **버전 0.2.11 기반 검증 중**, v1.0 미발행으로 인수한다.

## 6. 지원하지 않는 작업

- 기존 Git 기록이나 사용자의 로컬 프로젝트 폴더 초기화/삭제
- 앱 소스를 따라 개인 운영 자격을 추측·생성하거나 외부 서버 설정을 임의 수정
- 실제 효과 확인 목적의 보안 조치 집행, 확인 번호·토큰 등 민감 자료 출력
- 전체 지원·백업 성공·복원 완료·신규 환경 재현 완료를 근거 없이 선언
- 미조회·부분 실패·unknown을 정상/안전/취약점 없음으로 치환

이 계획은 [22단계 릴리스 현황](STUDENT_STAGE22_RELEASE.md) 및 [22단계 새 폴더 재현 기록](STUDENT_STAGE22_REPRODUCTION.md)과 같은 코드 기준으로 읽어야 한다.
